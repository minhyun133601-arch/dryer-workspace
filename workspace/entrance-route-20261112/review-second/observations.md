# 11/12 경비실~2팀 입구 영상 · 140~288초 판독

원본 288.216초 영상의 후반을 2초 간격 75장으로 추출하고 접촉시트 5장과 핵심 38장 원본(1080×1920)을 직접 확인했다. `frames/`, `native/`, `contact-*.jpg`에 시각별 근거를 보관한다. 원본 회전 -90°를 ffmpeg가 자동 적용했다. 좌표와 건물 크기는 기존 모델을 유지하며, 새로 보이는 처마·문·가드·실외기 치수는 영상 비례 근사다.

## 위치 대응과 정정 이력

연속 이동 순서로 x23 휴게실→x20.65 타공문→x17.55 단일셔터→x14 승강기→x5 쌍셔터→x-3.1 보온관→x-5 노란 계단문을 대응시켰다. 카메라가 248초에 위로 향하며 화면의 좌우가 달라 보이므로, 한 장의 유리 매스 위치만으로 문을 대응시키면 안 된다.

초기 접촉시트 단계에서 노란문을 x14 유리문 대체로 잠정 해석했으나, 194→226→242→254초 연속 원본으로 재확인해 철회했다. 최종 구현은 x14=승강기, x-5=노란문이다.

사용자 강조에 따라 승강기220~244초는0.25초간격97장, 2팀문260~288초는0.5초간격57장을 추가 추출해 직접 전수 확인했다. `elevator-motion/`, `entry-motion/`이 최신 상세판독 근거다. 손으로 문짝을 당기는 경첩문이 아니라, 왼쪽 호출버튼을 누르면 옆으로 열리는 승강기문임이 확인된다.

2팀문은 273.0초 실외기 지상열 정면→273.5초 유리문 정면, 281.0초 지상열 끝→281.5초 문 정면에서 카메라가 약90도 돌아간다. GPS camera_direction도272/280초 실외기통로장축118.6°/119.5°,274/282초 문 정면15.2°/9.0°로 약100°차다. GPS 절대 좌표·방위에는 약1.4~1.6m 표기오차와 시간추정/자기장편차가 있으므로 현장 실측으로 쓰지 않고, 연속 모서리 형태와 상대 회전을 보조하는 데 사용했다.

사용자가 2팀 입구 위치를 확인한 뒤 문 앞 여유를 더 넓혀 달라고 요청해, 실외기 가대·장비4+7+2·사다리 전체를 root-local -X방향1.5m 옮겼다. 이 이동은 `user-requested-door-clearance-20261112`로 기록한 시각 여유 조정이며 영상에서 실측한 좌표 변경이 아니다. 문 위치와 리턴벽 방향은 유지했다.

`check_entry_clearance.mjs`에서 새 문 전면 x6.55..9.05/z-2.9..-.4/y.1..2.6의 2.5m 폭 접근 영역과 실외기 가대·장비의 실제 월드 bbox를 대조해 간섭0을 확인했다. 가장 가까운 지상 실외기 외곽은x5.725이며 문 면x9.1과3.375m 떨어져 있다(이격 전1.875m). 실제문 앞에 임의의 중복 실외기나 가드를 추가하지 않았다.

리턴벽의 문은 바닥과 맞닿는 구멍이므로 외곽에 닿는 Shape.holes를 쓰지 않고 좌·우 기둥과 문 위 인방3개 실체로 나누었다. y.4/1.3/2.2 높이의 실제 문 개구부 raycast가 모두 열려 있음을 `entrance-route.test.mjs`가 확인한다.

## 구현·검증

수정 앱 파일은 `apps/site/rear-survey-data.js`, `apps/site/rear-stair-models.js` 두 개다. 기존 설비 ID·카탈로그 위치·자동문 연결과 3개의 선택 parts를 유지했다. 모든 새 sourceTimes는 `guardhouse-team2-video-20261112`로 태그했고, 기존 11/11 근거와 혼동하지 않는다.

`rear-stair-models`/`campus-rear-models` 16개 테스트 통과. `campus-scene`의 기존 도로간격 bbox 검사는 새 지상 맨홀/드레인이 전체 bbox에 잡혀 옛8~18m 조건과 달라 parent에 실제 벽체 기준으로 검사 요청했다. 2팀문 worldX10.6/평행후면벽이라는 기존 고정 assertion도 새 상대벽 방향과 위치에 맞춰 parent가 갱신한다. 별도 문 옆 실외기 중복 추가는 철회해 bank 수량4+7+2를 유지한다.
